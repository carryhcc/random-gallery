# Baseline Profile：冷启动关键路径
#
# AGP 会把本文件合并进 APK，profileinstaller 在设备首次空闲时据此编译 AOT 镜像，
# 让下面这些方法在后续启动中免去 JIT 解释执行与 profile 采样，直接走机器码。
#
# 覆盖范围 = Application.onCreate → MainActivity.onCreate → 首帧 HomeScreen 这条链路。
# 刻意不写「所有方法」——过度膨胀的 profile 会拉长 dexopt 时间、挤占磁盘，收益反而下降。
#
# 格式：HSPL（human-readable simple profile line）。AGP 的 compileArtProfile 会严格校验，
# 写错直接构建失败 —— 这里的三条规则都是踩过的坑：
#   Lcom/foo/Bar;                              —— 类。**不能**带 H/S/P 前缀
#   Lcom/foo/Bar;->m()V                        —— 方法。**必须**带 H/S/P 之一：H=热点，S=启动期，P=启动后
#   HSPLcom/foo/Bar;->m()V                     —— 启动期关键路径
# 早期版本在类规则上误加了 HSPL 前缀（如 HSPLandroidx/activity/EdgeToEdge;），
# 因当时无人执行过该任务而未被发现。
#
# 注意：混淆后的类名（release 走 R8）无需在此处理——R8 会把这里的条目映射到重命名后的
# 符号上；已删除的方法会被直接丢弃。
